Variables

Caper supports two kinds of variables that can be interpolated into step values using {{variable_name}} syntax.

Team Variables

Static key-value pairs defined in Variables. Substituted into the script before it runs. Useful for environment-specific values like base URLs, usernames, or API keys.

Example — Navigate step using a team variable
URL{{BASE_URL}}/products

If BASE_URL is set to https://shop.example.com in Variables, the test will navigate to https://shop.example.com/products.

Runtime Variables

Captured during test execution by steps like Pick Random Element. Available to all subsequent steps in the same run via {{variable_name}}.

Custom Steps

The following step types are unique to Caper. They are built on top of standard Playwright but expose higher-level behaviour not available natively.

Pick Random Element

Conditionals

Selects a random element from all DOM nodes matching a CSS selector, captures a value from it, stores it in a named variable, and optionally clicks it. Use this to test flows that should work with any item in a list — product cards, search results, table rows, etc.

Fields

FieldRequiredDescription
CSS Selector (candidates)YesMatches all candidate elements. Must be a CSS selector — class, tag, attribute, or a combination.
Exclude selectorNoAny candidate that also matches this selector is excluded from the pool before picking. Use to skip sold-out, disabled, or unavailable items.
Capture attributeNoIf set, captures this HTML attribute from the picked element (e.g. data-sku, href). If left blank, captures the element's inner text.
Store as variable nameYesThe captured value is stored under this name. Reference it in later steps as {{name}}.
Click picked elementYesWhether to click the picked element after capturing. Set to no if you only want to capture a value without navigating.

How it works

  1. Waits for the first matching element to be attached to the DOM (10s timeout).
  2. Fetches all matching elements via page.locator(selector).all().
  3. Filters out any elements that also match the exclude selector.
  4. Picks one at random.
  5. Captures inner text or an attribute, stores it in the runtime variable store.
  6. Optionally clicks the picked element.

The step result message always shows exactly which item was picked, so failed runs are fully traceable.

Example — Add a random product to basket

A product list page where each card has the class product-card. We want to pick one at random, navigate to its detail page, and add it to the basket.

Sample HTML
<div class="product-list">

  <div class="product-card">
    <a href="/products/blue-widget" class="product-link">
      <img src="/img/blue-widget.jpg" alt="Blue Widget">
      <h3 class="product-name">Blue Widget</h3>
      <p class="product-price">€29.99</p>
    </a>
    <button class="add-to-basket">Add to basket</button>
  </div>

  <div class="product-card">
    <a href="/products/red-gadget" class="product-link">
      <img src="/img/red-gadget.jpg" alt="Red Gadget">
      <h3 class="product-name">Red Gadget</h3>
      <p class="product-price">€49.99</p>
    </a>
    <button class="add-to-basket">Add to basket</button>
  </div>

  <!-- ...more cards -->

</div>

Example — Skip sold-out items

Same product list, but some cards have a sold-out class added when stock is zero. We want to pick only from available items.

Sample HTML — mix of available and sold-out
<div class="product-list">

  <div class="product-card">
    <a href="/products/blue-widget" class="product-link">
      <h3 class="product-name">Blue Widget</h3>
      <p class="product-price">€29.99</p>
    </a>
    <button class="add-to-basket">Add to basket</button>
  </div>

  <div class="product-card sold-out">
    <a href="/products/red-gadget" class="product-link">
      <h3 class="product-name">Red Gadget</h3>
      <p class="product-price">€49.99</p>
    </a>
    <span class="sold-out-label">Sold out</span>
  </div>

  <div class="product-card">
    <a href="/products/green-doohickey" class="product-link">
      <h3 class="product-name">Green Doohickey</h3>
      <p class="product-price">€9.99</p>
    </a>
    <button class="add-to-basket">Add to basket</button>
  </div>

</div>
Step configuration — exclude sold-out cards
CSS Selector.product-card .product-name
Exclude selector.sold-out
Capture attributeleave blank
Store asselected_product
Click picked elementyes

The exclude selector is evaluated against the candidate element (the .product-name h3), not the card. To match against the parent card, use :is(.sold-out) .product-name or target the card directly as the candidate selector: .product-card:not(.sold-out) .product-name — which is often the cleanest approach.

Tip — cleanest sold-out exclusion
CSS Selector.product-card:not(.sold-out) .product-name
Exclude selectorleave blank

Using :not() directly in the candidate selector is simpler and more reliable than using the exclude field when the out-of-stock marker is on a parent element.

Click If Exists

Conditionals

Clicks an element if it is present and visible in the DOM. If the element is not found, the step is skipped silently and the test continues. The step never fails due to the element being absent.

Use this for elements that appear inconsistently — cookie consent banners, promotional modals, "continue as guest" prompts, newsletter popups, or any overlay that only shows on first visit or under certain conditions.

Fields

FieldRequiredDescription
Selector TypeYesHow to locate the element — CSS, ID, XPath, etc.
SelectorYesThe selector value. Targets the element to click.

Step result statuses

StatusMeaning
successElement was found and visible — clicked successfully.
skippedElement was not found or not visible — step skipped, test continues.
errorElement was found but the click itself threw an exception.

Example — Dismiss cookie banner

A cookie consent banner that appears on the first visit but not on subsequent ones. Adding this step before any navigation ensures the banner is dismissed if present, without breaking runs where it is absent.

Sample HTML
<div id="cookie-banner" class="consent-overlay">
  <p>We use cookies to improve your experience.</p>
  <button id="cookie-accept" class="btn-accept">Accept all</button>
  <button id="cookie-reject" class="btn-reject">Reject</button>
</div>
Step configuration
Selector Typecss
Selector#cookie-accept
Recommended test flow
  1. Navigate — go to the page
  2. Click If Exists — #cookie-accept
  3. Continue with the rest of the test normally

Works regardless of language — the selector targets the element directly, not any text inside it, so French, German, or Danish cookie banners work identically.
